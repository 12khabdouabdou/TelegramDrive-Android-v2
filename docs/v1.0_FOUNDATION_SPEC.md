# Spec: Foundation Re-Architecture v1.0

## Objective

**Problem:** ALL features broken on Samsung Android 14+. Root cause: `EncryptedSharedPreferences` (alpha library) fails on Samsung Knox-managed keymaster, invalidating both API creds and TDLib session key. No recovery path exists.

**Goal:** Replace the fragile secure storage foundation with a robust, recoverable design. Fix all foundation-level bugs identified in the audit. Provide a test checklist to verify every feature works.

## Root Causes (priority order)

1. **C1 — EncryptedSharedPreferences is a single point of failure** (Samsung Knox invalidates master key → all features fail)
2. **C2 — Missing FileProvider in manifest** (open-file actions silently fail)
3. **C3 — TDLib native lib loading has no diagnostics** (UnsatisfiedLinkError silently kills TDLib)
4. **H1 — No binlog-corruption recovery** (corrupt TDLib DB = permanent brick)
5. **H4 — DataStore has no corruption recovery**
6. **H3 — Foreground service not defensively declared**

## Fixes

### Fix 1: KeystoreHelper — recoverable secure storage
- Wrap `EncryptedSharedPreferences.create()` in try/catch
- On failure: delete master key + prefs file, retry once
- Fix `clear()` to delete the CORRECT alias (`MasterKey.DEFAULT_MASTER_KEY_ALIAS`)
- Add a `resetSecureStorage()` method for explicit recovery

### Fix 2: FileProvider declaration
- Add `<provider>` to AndroidManifest.xml
- Verify `file_paths.xml` covers all directories

### Fix 3: TDLib native loading diagnostics
- Wrap `Client.create()` in try/catch
- On `UnsatisfiedLinkError`: log device ABI + available .so files
- Throw a typed exception with a clear message

### Fix 4: Binlog corruption recovery
- In `initialize()`, if `SetTdlibParameters` fails with DB error, delete `db/` dir, regenerate key, retry once

### Fix 5: DataStore corruption recovery
- Add `.catch { emit(defaults) }` to `AppPreferences.data`

### Fix 6: Foreground service declaration
- Explicitly declare `SystemForegroundService` with `dataSync` type

## Testing Strategy
- Existing 18 unit tests must still pass
- Manual test checklist (provided to user after build)

## Success Criteria
1. App launches on Samsung Android 14+ without crashing
2. Login works (API creds → phone → code → password)
3. Browse files works (Saved Messages + folders)
4. Upload single file works
5. Upload folder as ZIP works
6. Download works
7. AutoBackup "Run now" works without crash
8. Search works
9. Folder management (create/rename/delete) works
10. Settings persist
11. Biometric lock triggers and unlocks
12. Open-file (external app) works

## Boundaries
- **Always:** Test before build, preserve existing DB schema (v3), keep backward compat where possible
- **Ask first:** Schema changes, new dependencies
- **Never:** Delete user's TDLib session without explicit user action
